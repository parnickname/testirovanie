# Простой трекер задач

Учебный проект: минимальное веб-приложение для практической работы по
тестированию ПО методом «чёрного ящика». Состоит из простого бэкенда на Go
(стандартная библиотека, без внешних зависимостей) и простого фронтенда на
HTML/CSS/JS без фреймворков.

Функциональность:
- добавление задачи (название + приоритет);
- отметка задачи как выполненной;
- редактирование названия задачи;
- удаление задачи;
- фильтрация списка: «Все» / «Активные» / «Выполненные»;
- счётчик оставшихся задач.

## Требования

- Установленный [Go](https://go.dev/dl/) версии 1.21 или новее.
- Никаких дополнительных зависимостей, баз данных или пакетов ставить не
  нужно — фронтенд встроен в бинарник бэкенда через `go:embed`.

Проверить версию Go:

```bash
go version
```

## Запуск

Из корня репозитория выполнить:

```bash
go run main.go
```

В консоли появится сообщение:

```
Сервер запущен: http://localhost:8080
```

Открыть в браузере адрес **http://localhost:8080** — откроется страница
приложения.

Остановить сервер — `Ctrl+C` в терминале, где он запущен.

### Сборка бинарника (по желанию)

```bash
go build -o tasktracker .
./tasktracker
```

## Устройство проекта

```
.
├── main.go            # HTTP-сервер и REST API (/api/tasks)
├── go.mod
├── frontend/           # статический фронтенд (встраивается в бинарник)
│   ├── index.html
│   ├── style.css
│   └── app.js
├── BUGS.md             # описание намеренно внесённых ошибок
└── README.md
```

Данные хранятся только в памяти процесса (без базы данных) — при перезапуске
сервера список задач сбрасывается к трём стартовым примерам.

## API

| Метод | Путь               | Описание                     |
|-------|--------------------|-------------------------------|
| GET   | `/api/tasks`       | получить список всех задач    |
| POST  | `/api/tasks`       | создать задачу                |
| PUT   | `/api/tasks/{id}`  | обновить задачу                |
| DELETE| `/api/tasks/{id}`  | удалить задачу                 |

## Примечание

В приложении намеренно оставлено 5 ошибок для последующего тестирования —
их описание и способы обнаружения находятся в файле [`BUGS.md`](BUGS.md).
Этот файл не предназначен для команды-тестировщика — он для внутреннего
использования при подготовке отчёта.
