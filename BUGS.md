# Описание внесённых ошибок

В приложение «Простой трекер задач» намеренно внесено **5 ошибок** разной
природы (логические, интерфейсные, ошибка валидации). Документ предназначен
для авторов продукта и не является отчётом о тестировании — сами ошибки
должны быть найдены тестировщиком методом «чёрного ящика», без обращения к
исходному коду.

Все ошибки живут во фронтенде: `frontend/app.js` (backend в `main.go`
специально оставлен рабочим и без ошибок валидации, кроме той, что описана
в ошибке №5).

---

## Сводная таблица

| № | Тип ошибки | Компонент | Критичность |
|---|------------|-----------|-------------|
| 1 | Логическая | Фильтрация списка задач | Средняя |
| 2 | Логическая | Счётчик оставшихся задач | Низкая |
| 3 | Логическая / интерфейсная | Удаление задачи | Высокая |
| 4 | Логическая (потеря данных) | Редактирование задачи | Высокая |
| 5 | Валидация | Добавление задачи | Средняя |

## Ошибка №1. Инверсия фильтров «Активные» / «Выполненные»

- **Расположение.** `frontend/app.js`, функция `getFilteredTasks()`.
- **Суть ошибки.** Фильтр «Активные» показывает задачи с `done === true`
  (то есть выполненные), а фильтр «Выполненные» — задачи с `done === false`
  (то есть активные). Условия перепутаны местами.
- **Как найдёт тестировщик.**
  1. Добавить 2–3 задачи, отметить часть из них как выполненные (галочка).
  2. Нажать вкладку «Активные» — в списке окажутся задачи с зачёркнутым
     текстом (то есть уже выполненные).
  3. Нажать вкладку «Выполненные» — в списке окажутся невыполненные задачи.
  4. Ожидаемый результат: «Активные» показывает только невыполненные
     задачи, «Выполненные» — только отмеченные галочкой. Фактический
     результат — списки перепутаны местами.

## Ошибка №2. Счётчик «Осталось задач» не учитывает выполненные

- **Расположение.** `frontend/app.js`, функция `updateCounter()`.
- **Суть ошибки.** Счётчик всегда выводит общее количество задач
  (`tasks.length`), не вычитая уже выполненные.
- **Как найдёт тестировщик.**
  1. Создать 2 задачи, зафиксировать значение счётчика (например, «Осталось
     задач: 2»).
  2. Отметить одну задачу как выполненную (поставить галочку).
  3. Ожидаемый результат: счётчик уменьшится до «Осталось задач: 1».
     Фактический результат: значение не меняется и остаётся «Осталось
     задач: 2».

## Ошибка №3. Удаление «не той» задачи при активном фильтре

- **Расположение.** `frontend/app.js`, функции `createTaskElement()` и
  `deleteTask(index)`.
- **Суть ошибки.** Кнопка «Удалить» передаёт порядковый номер задачи
  внутри **отфильтрованного** (видимого) списка, а сама функция удаления
  применяет этот номер как индекс к **полному** массиву задач `tasks`.
  Если отображается не полный список (например, применён фильтр), номера
  расходятся, и удаляется задача, отличная от той, на которой нажали
  «Удалить».
- **Как найдёт тестировщик.**
  1. Создать не менее 3 задач так, чтобы среди них была и выполненная, и
     невыполненные (порядок создания важен).
  2. Переключиться на любой фильтр, отличный от «Все» (например,
     «Выполненные»), так чтобы список показывал не все задачи.
  3. Нажать «Удалить» у задачи, которая **не первая** в отфильтрованном
     списке, и запомнить её название.
  4. Переключиться обратно на фильтр «Все» и сверить список.
  5. Ожидаемый результат: исчезла именно та задача, у которой нажали
     «Удалить». Фактический результат: исчезает другая задача, а та, что
     тестировщик пытался удалить, остаётся в списке.
  6. Примечание: при фильтре «Все» баг не проявляется (индексы совпадают),
     поэтому важно проверять именно на отфильтрованном списке.

## Ошибка №4. Изменение названия задачи не сохраняется

- **Расположение.** `frontend/app.js`, функция `saveEdit(id, newTitle)`.
- **Суть ошибки.** При нажатии «Сохранить» новое название задачи
  записывается только в локальную переменную `tasks` в браузере и
  немедленно отображается на экране, но запрос на сервер (`PUT
  /api/tasks/:id`) не отправляется. После перезагрузки страницы список
  запрашивается заново с сервера, где значение осталось старым.
- **Как найдёт тестировщик.**
  1. Нажать «Изменить» у любой задачи.
  2. Изменить текст и нажать «Сохранить».
  3. Убедиться, что на экране показано новое название (кажется, что всё
     сохранилось).
  4. Перезагрузить страницу (F5).
  5. Ожидаемый результат: новое название сохраняется и после перезагрузки.
     Фактический результат: после перезагрузки возвращается старое
     название.

## Ошибка №5. Возможность добавить пустую задачу

- **Расположение.** `frontend/app.js`, функция `addTask(e)` (значение поля
  ввода не проверяется на пустоту/пробелы перед отправкой); дополнительно
  `main.go`, обработчик `POST /api/tasks` не проверяет `title` на сервере.
- **Суть ошибки.** Форма позволяет нажать «Добавить», не заполнив поле
  «Название новой задачи» (или заполнив его одними пробелами). В список
  добавляется пустая строка-задача.
- **Как найдёт тестировщик.**
  1. Оставить поле «Название новой задачи» пустым (или ввести только
     пробелы).
  2. Нажать «Добавить».
  3. Ожидаемый результат: задача не создаётся, форма требует ввести
     название (например, подсветка поля или сообщение об ошибке).
     Фактический результат: в списке появляется новая пустая строка без
     текста, которую невозможно осмысленно отличить от остальных задач.
